# LibreOffice Writer cluster — layout, standards, debugging timeline

Source of truth: `/home/agent/workspace/playground/cluster/` (files: `conductor.py`,
`history_db.py`, `tracker.py`, `standards.md`, `status.md`). History DB:
`playground/data/cluster_history.db` (append-only). Status report:
`cluster/status.md`, regenerated by `tracker.py` (deterministic, no LLM).

## Layout / roles

- Read-only index clone: `/home/agent/workspace/libreoffice-core` (agents read here).
- Writable work clone: `/home/agent/workspace/lo-writer`; remote `origin` =
  `yolka-wiz/libreoffice-work` (own repo, was EMPTY — bootstrap needed), `upstream`
  = `LibreOffice/core`.
- Pipeline: claim → searcher upstream check (GREEN/ALREADY_UPSTREAM) →
  inspector_a investigate (root cause + file:line + verification level V0-V3) →
  inspector_b implement (branch `writer/<bug-id>-<slug>`, commit, push, switch
  master) → conductor records commit → tracker publishes `cluster/status.md` +
  result to the results repo.
- Driver: cron `lo-writer-cluster-tick` (`*/30 * * * *`, no_agent, runs conductor).
- Queue: 5 seeded sw/ tasks (tdf#90152, tdf#35055, opt-f1, tdf#119931, tdf#82579).

## Standards highlights

- One problem per branch; never touch `workdir/`, `external/`, `config_host/`,
  `solenv/` (generated/third-party); no secrets; every step logged.
- Verification: V0 unverified (state why) / V1 static / V2 script test / V3 compiled.
- Commit format: `tdf#<id> <summary>` + body what/why/how-verified + Change-Id.
- Full LO build is hours — cluster does not run it; upstream Gerrit CI is final gate.

## Debugging timeline (2026-08-10) — the failures that taught the lessons

1. **Task#1 blocked: inspector_a TIMEOUT after 900s** (twice; task#2 also
   stuck-investigating). Fix: `MAX_STEP_SECONDS` 900 → 1800. Requeue blocked
   tasks manually (`pending`) — queue picks pending only.
2. **inspector_a investigation succeeded but inspector_b produced nothing** —
   first run: empty `writer/*` branch, run ended right after an FTS5 error
   (`fts5: syntax error near "#"` on `memory_search('tdf#90152 …')`). Fix in
   `memory_store.py`: `_fts5_safe_query()` (tokenize word chars, quote phrases,
   AND-join) + try/except fallback to vector-only.
3. **Second run: inspector_b full timeout, no branch.** Root cause: inspector_b
   had git tools but NO file-write tool — structurally unable to edit `doc.cxx`.
   Fix: added `git_write_file` + `git_patch_file` (path-escape guard, single-
   replace with ambiguity check) to `tools/git_tools.py`.
4. **Conductor misdetection**: success check used `git branch --show-current`
   (agent switches back to master after push) → reported "no branch" even for
   good fixes. Fix: list `writer/*` + require a commit beyond master.
5. **Pushes never landed**: origin `yolka-wiz/libreoffice-work` was EMPTY (0 KB).
   Any push = full ~350 MB snapshot upload; HTTPS chunked hung, SSH truncated
   around index-pack; only small pushes succeeded. Bootstrap: switch origin to
   SSH (`git remote set-url origin git@github.com:...`), push `master` (big,
   slow, may need keepalives: `GIT_SSH_COMMAND="ssh -o ServerAliveInterval=15
   -o ServerAliveCountMax=4 -o TCPKeepAlive=yes"`), then writer branches are tiny.
   First pushed branch to an empty repo becomes the DEFAULT branch (can't delete
   until another branch exists and default is switched). Verify landing with
   `gh api repos/<owner>/<repo>/branches`.
6. **Fixes that worked**: FTS5 sanitize, git write/patch tools, conductor
   branch detection, 1800s budget. With all four in place, task#1 went through:
   commit `76898c2b` on `writer/tdf-90152-postit-print-locale` (+39/−11 in
   `sw/source/core/doc/doc.cxx`, locale-aware list separator + bold labels —
   follows the maintainer's "don't ship the naive English-only fix" warning).

## Optimization findings (separate, published to results repo)

(invert N50 per-call shader alloc — in-source TODO), `sw/source/core/text`

GetOptimalColWidth), `configmgr` (serial XCS/XCU parse on startup critical path).

fetch — full `--unshallow` consistently fails on this link with early EOF;
small `--shallow-since`/`--depth` fetches work).
